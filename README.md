
# 🎮 DealShark v1 (Teaching Repo)

This repository contains the **DealShark v1** project used in the module:

**Designing and Developing Web Applications (UG409759)**  
**BSc Computing**

It is a structured teaching example used to demonstrate:

- Foundational CSS layout using **Flexbox** and **Grid**
- Token based CSS design systems
- Structuring a small front-end web application
- Asynchronous JavaScript
- Working with the **fetch API**
- Consuming data from the **CheapShark API**
- Basic state management in JavaScript
- Progressive feature development across multiple weeks

This is **version 1** of the application. The project is intentionally built using HTML, CSS and JavaScript first, before being re-made and completed later using **Angular**.

---

## 📌 Important

This repository is primarily for **reference and catch-up support**.

It is strongly recommended that you:

✅ Follow the live demos each week  
✅ Complete exercises yourself  
✅ Use this repo only when you need to check a solution or catch up  

Resist the urge to copy and paste. You’ll learn far more by building the features yourself.

## 🌿 Branch Structure (Learning Timeline)

The `0-starting-point` branch is the **starting point** containing the scaffolded project and starting token based design system.

From there, each branch represents the project state at the **end of a teaching block or exercise**.

Branch progression:

| Branch Name | Content |
|---|---|
| `main` | Main branch, finished version 1 application |
| `0-starting-point` | Starting project scaffolded with a token based CSS design system |
| `1-design-complete` | Homepage design created using Flexbox and Grid |
| `2-complete` | Deal list populated using the CheapShark API |

If you fall behind or want to compare your work, switch to the appropriate branch.

---

## ⚠️ Notes

- Branches represent learning checkpoints, not production quality code
- Some implementations prioritise clarity for learning over optimisation
- CSS structure and JavaScript state management are introduced progressively
- API handling is kept deliberately simple at this stage
- This version is designed to support the later Angular version of the application
